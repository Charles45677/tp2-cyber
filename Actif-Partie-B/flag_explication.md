| Épreuve / Flag | Justification et Méthode Technique |

| **Reset Password**<br>`FLAG-780148277700634510869553303` | **1. Analyse de l'API :**<br>- J'ai ouvert la page `/resetpasswordstatus` de l'API (`http://192.168.1.209:4444`) pour récupérer la liste des 19 nombres aléatoires générés par Java (`java.util.Random`).<br>- *Source technique :* [`java.util.Random` (Documentation officielle Oracle)](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Random.html).<br><br>**2. Recherche de la graine (*seed*) :**<br>- En Java, la classe `java.util.Random` fabrique ses nombres à partir d'un point de départ appelé *seed* (souvent l'heure exacte en millisecondes).<br>- Grâce à un programme Java (`AttaqueReset.java`) utilisant [`HttpURLConnection`](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/net/HttpURLConnection.html) et [`BufferedReader`](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/io/BufferedReader.html), j'ai récupéré le premier nombre de la liste.<br>- Mon script a ensuite testé par tâtonnement les heures proches pour retrouver le bon *seed* utilisé par le serveur.<br><br>**3. Prédiction et obtention du Flag :**<br>- Une fois le bon *seed* trouvé, le script recree le générateur, passe les 19 premiers nombres, puis calcule exactement le 20e nombre (**`randomNumber20`**).<br>- Le script a ensuite envoyé ce nombre secret à l'API via le lien (`http://192.168.1.209:4444/changepassword?secret=)avant le changement des 3 secondes, ce qui m'a retourné le flag. |
